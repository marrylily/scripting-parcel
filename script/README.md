# 包裹助手（远程更新 1.2.6）

这是在 1.2.5 之上的**远程更新版**。导入后不会自动覆盖原来的「包裹助手」或更早的远程更新副本。请作为已导入的「包裹助手（远程更新）」检查更新，或作为新脚本导入，原脚本先留着。

导入与远程更新的完整说明见仓库根目录 README（GitHub 上与本文件同级的上一层）。

相对 1.2.0 只改了同步过程中可安全改的部分，并加上远程更新配置：

- 同步结束后，按钮右侧会显示脱敏后的失败原因（不会再只显示「尚未同步」却没有任何错误）
- 手动全量时先同步菜鸟（不走 WebView），淘宝失败时不再挡住菜鸟
- 淘宝发现订单的循环会查看已有的协作式 deadline（`Date.now()`），预算不够时不再打开最长约 3 分钟的人机验证页
- 1.2.1 曾增加 `setTimeout` / `Promise.race` 硬超时，真机上报了「Timer requires its active script on the main…」，1.2.2 / 1.2.3 已撤销新增竞速
- 1.2.4 进一步把原包里主机侧的 `setTimeout` / `setInterval`（含淘宝 `pageTimeout`、重试 `delay`、单条刷新 `timeoutWrap`、小组件外层竞速等）改为安全包装：调度失败时不加硬超时、不把 Timer 错误当成同步失败。WebView 注入到页面里的定时器未改
- 手动同步开始时清除该平台在 App Group（`cc/syncErr.json`）中的旧失败记录；新失败文案带版本号和时间，例如 `1.2.4 11-17 12:00：…`
- 1.2.5：打开 App / 下拉刷新时，淘宝等网页平台按前台间隔（默认约 20 分钟，至少 15 分钟）参与全量发现，不再被小组件先跑通的接口平台或轻量刷新时间戳整轮挡住
- 被跳过（无 WebView、间隔未到、时间不够等）会在设置页显示带版本号的原因，例如 `1.2.5 11-17 13:10：当前环境没有 WebView，请在 App 内同步`
- 全量成功（包括 0 个新订单）仍会更新该平台的「上次同步」时间；点「立即同步」仍然无视间隔
- 1.2.6：淘宝超时不再笼统写成「网络超时」；文案带版本号、步骤名、耗时和当前页 host+path。加载失败会重试一次；若已跳到登录/验证页，会提示「需重新登录或完成验证」。淘宝设置页有「诊断」显示各步耗时（脱敏）。手动同步预算约 3 分钟。使用 Surge 时请把淘宝/阿里域名设为直连，见仓库根 README
- 因此本版**不能保证**同步一定在两分钟内结束，也**不能保证**按钮在挂住时一定会从「同步中」收回（Timer 不可用时不再加硬超时）
- 未改登录、人机验证流程、快递鸟域名、密钥来源、`runInApp` 或 `Script.exit`

# 包裹助手

在 Scripting 里管理快递取件码：自动同步在途与待取、到站提醒、驿站匹配、位置提醒、桌面小组件、实时活动。

## 首次使用

1. 打开「设置 → 平台授权」，按需登录淘宝 / 京东 / 拼多多 / 菜鸟 / 丰巢 / 小米等平台；只授权你要用的，未授权的平台不联网。
2. 也可以不用授权：包裹页右下角「＋」进入搜索添加，输入运单号查询即可；快捷指令识别出的短信/截图也会自动归档。
3. 到「设置 → 取件提醒」打开提醒，并允许 Scripting 发送通知。

## 权限说明

- 通知：到站提醒、超时提醒、位置提醒。
- 定位：只有你主动添加「位置提醒」时才会用；选「始终」需要在系统设置里手动开一次。
- 网络：各平台官方域名与快递鸟接口；手动查单需要自动判断快递公司时调用快递100 的公开接口；物流详情里的路线用 OSRM 公共路由服务。不连接任何自建服务器。

## 数据与隐私

- 所有包裹、驿站、位置、设置都存在本机（Scripting Storage），不上传任何服务器。
- 短信只在本机解析，不发送到第三方。
- 平台登录态存在系统钥匙串；可在「平台授权」里逐个解除。
- 「设置 → 清除缓存」会删除 **已取超过 30 天** 的历史包裹（连同其轨迹与提醒），重置统计里的两项累计数（按剩下包裹重算），并清掉旧识别记录、身份码缓存、诊断日志与图标副本；在途、待取、设置与授权不动。

## 统计口径

- 累计快件：导入过这个 App 的快递总数，只增不减（清缓存时按剩余重算）
- 累计已取：历史上点过「已取」的包裹数，只增不减（同上）
- 月均取件、最常取件驿站、本月取件、当前待取、取件趋势均按当前列表计算

## 小组件

- 支持小、中、大与锁屏 accessory 尺寸；页脚只有同步时间，不显示版本号。
- 组件自己读共享快照出图，并在出图后限时（3 秒）刷新：已有包裹走轻量刷新，同时按「全量轮转」每次最多补两个平台的新订单。不需要 App 在后台，也不依赖推送服务器。
- 单次唤醒的联网时间有限，网页类平台的抓取可能跨多次唤醒续跑；App 内同步不受此限制。

## 目录

- `index.tsx` 入口（tab + sheet 编排 + 小组件回跳）
- `store.ts` 数据层（包裹 / 驿站 / 亲友 / 位置提醒 / 设置）
- `widget.tsx` `widgetData.ts` 小组件；版式唯一实现在 `ui/widgetLayout.tsx`（桌面与设置页预览共用）
- `live_activity.tsx` 灵动岛 / 实时活动
- `app_intents.tsx` `intent.tsx` 小组件按钮与快捷指令入口
- `platforms.ts` 平台清单；`utils/` 各平台抓取、解析、提醒、调度
- `theme.ts` 配色与快递公司映射；`ui/` 页面与组件
- `assets/` 平台图标与快捷指令模板

## 开发

- 类型检查：`get_typescript_diagnostics`（项目「包裹助手」）应为 0 报错。
- 改组件代码必须同时改 `widgetVersion.ts` 里的 `WIDGET_VERSION`，否则首帧判定不生效。
- 组件时序与约束见 `WIDGET_NOTES.md`。
